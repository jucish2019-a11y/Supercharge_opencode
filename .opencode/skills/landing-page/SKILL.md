## What I do

I design landing pages that convert visitors into users — the specific page type with a single narrative arc, clear CTA hierarchy, and intentional scroll progression:

- **Hero section** — The dominant element that communicates value in 3 seconds
- **Social proof** — Credibility signals positioned where doubt appears
- **Feature/value sections** — Benefits framed as transformation, not capability
- **CTA hierarchy** — Primary action repeated at every decision point
- **Narrative arc** — The scroll tells a story: problem → solution → proof → action
- **AI tell avoidance** — Landing pages are the most AI-convergent page type

## When to use me

Use this skill when:
- Designing a product landing page, SaaS marketing page, or app homepage
- Converting an existing landing page that isn't performing
- Building a launch page for a new product
- Reviewing a landing page for conversion issues
- Avoiding the "AI landing page" look that every AI generates

## How I work

### Checker mode (auditing existing landing page)

1. **3-second test** — What does the page communicate in 3 seconds? If unclear, the hero fails.
2. **CTA clarity** — Is the primary action obvious? Is it reachable without scrolling all the way to the bottom?
3. **Narrative arc** — Does the page tell a story (problem → solution → proof → action) or is it a random section order?
4. **Social proof placement** — Does proof appear where doubt naturally arises?
5. **AI tells** — Run the strip-ai-tells checklist. Landing pages are the most AI-converged page type.

### Applier mode (building from scratch)

1. **Define conversion goal** — One primary action. Everything supports it.
2. **Write the narrative** — Problem, solution, proof, action — in that order.
3. **Design the hero** — Dominant element, value proposition, primary CTA.
4. **Build supporting sections** — Each section advances the narrative.
5. **Place CTAs** — At every point where the user might decide.
6. **Add social proof** — At every point where the user might doubt.
7. **Avoid AI tells** — Use the anti-default checklist before shipping.

## The narrative arc

A landing page is a story, not a bulletin board. The sections should follow a logical persuasive sequence:

```
1. PROBLEM (hero)
   "Your current situation is painful/inefficient/expensive"

2. SOLUTION (value proposition)
   "Here's how we solve it, in terms of your outcome"

3. HOW (features, but framed as transformation)
   "Here's what changes — not what the product does, but what you get"

4. PROOF (social proof, results, testimonials)
   "Others like you have gotten these results"

5. ACTION (final CTA)
   "Start now — it's easy/risk-free/immediate"
```

Every section must either advance the narrative or remove a doubt. If it does neither, cut it.

## Hero section design

The hero is the dominant element. It must communicate value in 3 seconds — the time before most visitors decide to stay or leave.

### Hero anatomy

```
┌─────────────────────────────────────────────┐
│ Navigation                                    │
├─────────────────────────────────────────────┤
│                                              │
│  HEADLINE                                    │  ← Largest text. States the
│  (value in one line)                         │     outcome, not the product
│                                              │
│  Subheadline                                 │  ← 1-2 lines. Expands the
│  (how, for whom, or why it's different)       │     headline with specifics
│                                              │
│  [Primary CTA]   Secondary link             │  ← Above the fold. Always.
│                                              │
│  Visual / Demo / Product screenshot          │  ← Shows the outcome, not
│                                              │     the interface
└─────────────────────────────────────────────┘
```

### Headline rules

- **State the outcome, not the product:** "Ship code 3× faster" not "AI-powered developer tools"
- **Be specific:** "Reduce deployment time from 45 minutes to 5" not "Faster deployments"
- **Name the audience:** "For teams shipping to production daily" not "For everyone"
- **Under 12 words:** If you need more, the value isn't clear enough yet

### CTA placement

The primary CTA must be visible without scrolling. It should also repeat at:
- After the features section (they've seen how it works)
- After social proof (they've seen it works for others)
- At the bottom of the page (final decision point)
- Optionally: a sticky CTA in the nav or a floating CTA on mobile

## Social proof placement

Place proof where doubt naturally arises, not just in a "trusted by" section:

| When they might doubt... | Place this proof... |
|--------------------------|---------------------|
| "Does this actually work?" | After the value proposition — results, metrics, case studies |
| "Is this legit?" | In or near the hero — logos, press mentions, user count |
| "Will it work for ME?" | After features — testimonials from similar personas |
| "Is it worth the cost?" | Near pricing — ROI data, savings calculations |
| "What if I hate it?" | Near the CTA — guarantee, free trial, cancel-anytime |

## Section design patterns

### The stat section

```
┌─────────────────────────────────────────────┐
│                                             │
│  75%                                        │  ← The stat: large, dominant
│                                             │
│  of engineering teams ship faster           │  ← Context: what the stat means
│  after adopting this workflow                │
│                                             │
│  — Stanford Web Credibility Research        │  ← Source: gives the stat authority
│                                             │
└─────────────────────────────────────────────┘

Why this works: A single large number + one line of context + a source
is more credible than a paragraph of explanation.
```

### The feature grid (done right)

Don't use identical icon+heading+text cards. Differentiate:

```
BAD (AI default):
  ┌──────┐ ┌──────┐ ┌──────┐
  │ icon │ │ icon │ │ icon │   All same size, same weight,
  │ head │ │ head │ │ head │   same layout. Nothing stands out.
  │ text │ │ text │ │ text │
  └──────┘ └──────┘ └──────┘

GOOD:
  ┌─────────────────────┐ ┌──────┐
  │                     │ │ head │   Featured item: 2× width,
  │  FEATURED FEATURE   │ │ text │   different layout, more detail.
  │  More detail about  │ ├──────┤
  │  the most important │ │ head │   Supporting items: compact,
  │  capability.        │ │ text │   equal weight, less detail.
  │                     │ ├──────┤
  └─────────────────────┘ │ head │
                          │ text │
                          └──────┘
```

### The proof section

```
┌─────────────────────────────────────────────┐
│  "This cut our deploy time from 45 minutes  │
│   to 5. We shipped 3 features this week      │  ← Specific, not generic
│   that would have taken a month."            │
│                                             │
│  — Sarah Chen, VP Engineering at Acme Corp   │  ← Named person and company
│                                             │
│  [Acme Corp logo]                            │  ← Logo adds credibility
└─────────────────────────────────────────────┘
```

## Landing page AI tells (most common)

Landing pages are the most AI-convergent page type. Run this checklist:

- [ ] Hero headline isn't "Revolutionize your workflow with AI-powered [product]" — AI default copy
- [ ] Not using cyan-on-dark or purple-to-blue hero gradient — AI default palette
- [ ] Not using glassmorphism on the hero CTA button — AI default decoration
- [ ] Feature grid isn't 3-4 identical icon+heading+text cards — AI default layout
- [ ] Sections aren't all center-aligned with equal spacing — AI default composition
- [ ] Testimonials aren't generic ("Great product, highly recommend") — AI default copy
- [ ] The page doesn't fade every section in from below with the same animation — AI default motion
- [ ] There's a clear narrative arc, not just sections stacked in a list

## Quality checklist

- [ ] Hero communicates value in under 3 seconds
- [ ] One primary CTA, visible without scrolling
- [ ] CTA repeats at 3+ points in the scroll
- [ ] Narrative arc: problem → solution → how → proof → action
- [ ] Social proof placed where doubt arises, not just grouped at the bottom
- [ ] Feature descriptions framed as outcomes, not capabilities
- [ ] At least one section breaks the grid pattern (featured item, full-bleed stat, etc.)
- [ ] No AI tells from the checklist above
- [ ] Mobile: hero text is legible, CTA is tappable, sections don't feel endless
- [ ] Above-the-fold content renders without JavaScript if possible (important for speed)

## Anti-patterns I avoid

- Describing features instead of outcomes — "AI-powered" means nothing; "saves 4 hours per week" means everything
- Putting all CTAs at the bottom — many visitors never scroll that far
- Using the same card layout for every section — visual monotony causes scroll fatigue
- Generic testimonials without names, companies, or specifics — "Great product!" is not proof
- Adding sections because competitors have them — every section must advance YOUR narrative
- Center-aligning everything — left-aligned body text reads better; asymmetric layouts have more character
- Making the hero a full-screen image with text overlaid — if the image is decorative, it's wasted space
- Treating the page as a list of sections with no relationship between them — the scroll IS the narrative
