## What I do

I structure content the way editorial designers do: as a narrative with pacing, tension, and release. Most AI-generated sites follow the same generic template (hero, features, testimonials, CTA, footer). I replace that with intentional content architecture where every section earns its position in the sequence.

- Map narrative arcs for pages (not just section lists)
- Define progressive disclosure levels (what you see first, what requires a scroll, what requires engagement)
- Specify data display grammar (when to use numbers, logos, diagrams, mockups)
- Set section-to-section tonal shifts so the page breathes and accelerates
- Design content density modes (compact, standard, comfortable)
- Replace generic placeholder content with realistic, credible data patterns

## When to use me

Use this skill when:
- Building any multi-section page (landing pages, product pages, marketing sites, portfolio pages)
- The content structure feels generic or follows the "hero then features then CTA" default
- You need to decide what information appears where and in what order
- The page needs to tell a story, not just list features
- Placeholder content (lorem ipsum, fake IDs, generic numbers) is undermining credibility

For related but distinct work:
- **landing-page** — Specific patterns for high-conversion landing pages (hooks, CTAs, social proof)
- **design-foundations** — Purpose, audience, aesthetic direction (the layer before content structure)
- **content-design** — UX writing, microcopy, tone of voice (the words themselves, not their architecture)
- **composition** — Visual arrangement of elements (how they look, not what they say or in what order)

## How I work

### Checker mode (auditing existing content architecture)

1. **Section inventory** — List every section in order. For each: what is it showing? What decision does it ask the reader to make?
2. **Narrative test** — Read the section headers in sequence. Do they tell a story with rising action, or is it a flat list?
3. **Disclosure audit** — What is visible at first glance (no scroll)? What requires one scroll? Two? Three? Is critical information buried?
4. **Density check** — Are all sections the same visual weight and information density? Or do they vary to create rhythm?
5. **Data realism check** — Is the content generic (lorem ipsum, "John Doe", "$5.00") or specific and credible (issue IDs, real decimal values, realistic names)?
6. **Tonal shift map** — Does the emotional register change across sections, or is it monotone?

### Applier mode (building content architecture from scratch)

#### Step 1: Define the narrative arc

Every page tells a story. Pick one:

| Arc | Pattern | Best for |
|-----|---------|----------|
| Resolution | Problem → Tension → Solution → Proof → Action | Product pages, SaaS landing pages |
| Revelation | Tease → Reveal → Expand → Deepen → Close | Product launches, portfolio pieces |
| Authority | Claim → Evidence → Scale → Trust → Access | Enterprise B2B, consulting, agencies |
| Education | Question → Explain → Demonstrate → Practice | Documentation, tutorials, developer tools |
| Immersion | Environment → Character → Conflict → Climax | Story-driven brands, creative portfolios |

The arc determines section order, not convention.

#### Step 2: Map information hierarchy

Rank every piece of content by importance. Then assign disclosure levels:

| Level | Visibility | Content type | Examples |
|-------|-----------|--------------|----------|
| L0: immediate | Hero area, no scroll | Core value prop, primary CTA | Headline, subhead, CTA button |
| L1: first scroll | 1-2 scrolls down | Key differentiators, primary proof | 3 feature highlights, 1 social proof block |
| L2: engaged | 3-5 scrolls | Detailed features, methodology, process | How it works, feature deep-dives |
| L3: committed | Deep scroll or interaction | Pricing, comparisons, technical specs | Pricing table, comparison matrix, API docs |
| L4: post-decision | Footer, post-CTA | Reassurance, navigation, legal | FAQ, guarantees, links |

Rules:
- L0 must communicate the entire value proposition in under 3 seconds
- L1 should create desire to scroll further (open loops, not closed ones)
- L2 rewards the reader who invested a scroll with substantive content
- L3 is for people already convinced — give them details, not persuasion
- L4 assumes the decision is made — facilitate, don't sell

#### Step 3: Design section-to-section tonal shifts

A page that maintains the same emotional register throughout feels flat. Premium sites shift tone between sections:

```
Section  Tonal register        Visual weight    Content density
-------  ----------------      -------------    ---------------
Hero     Confident, bold        Heavy            Low (few words, big impact)
Gap      Quiet, breathing      Negative space   None
Features Precise, technical     Medium           Medium (specific, not verbose)
Proof    Warm, credible         Medium-heavy      High (logos, numbers, detail)
Details  Dense, authoritative  Heavy             High (specs, data)
CTA      Urgent, clear         Medium            Low (clear ask, no clutter)
```

The tonal shifts create rhythm. Think of it like music: the rests matter as much as the notes. A section separator with generous whitespace after a dense proof section gives the reader cognitive rest before the CTA.

Shift techniques:
- **Breath** (whitespace gap between sections, 96-128px)
- **Pace change** (fast/sparse section followed by slow/dense section)
- **Voice shift** (headline voice → body voice → caption voice)
- **Color temperature** (cool section → warm section → neutral section)
- **Layout change** (full-width hero → contained grid → edge-to-edge data → contained CTA)

#### Step 4: Choose data display grammar

Each type of information has an optimal display format. Don't default to cards for everything:

| Information type | Best display | Avoid |
|-----------------|-------------|-------|
| Authority/credibility | Number with label (large stat) | Paragraph of text |
| Social proof | Logo wall (grayscale) | Named testimonials for B2B |
| Process/sequence | Numbered steps with connecting line | Bullet list |
| Comparison | Table or matrix | Side-by-side cards |
| Capability | Bento grid (mixed sizes, weighted) | Equal feature cards |
| Narrative | Full-width section with scroll progression | Carousel |
| Technical detail | Code block, API response, terminal output | Description list |
| Evidence | Timeline, changelog, audit trail | Generic "trusted by" section |
| CTA | Single button, generous whitespace, clear copy | Multiple buttons, boxed section |

#### Step 5: Set content density mode

Density affects every spacing, type size, and information decision in a section:

| Mode | Row height | Body size | Padding | Use for |
|------|-----------|-----------|---------|---------|
| Compact | 32px | 13px | 8-12px | Data tables, issue lists, admin dashboards |
| Standard | 40px | 15px | 16-20px | Primary task views, product pages, forms |
| Comfortable | 48px | 16-17px | 24-32px | Reading content, onboarding, marketing |

A single page can use multiple density modes. Linear uses compact density for issue lists and comfortable density for feature sections on their marketing site. The shift between densities creates visual variety.

#### Step 6: Fill with credible data

Generic content undermines credibility. Replace every placeholder with realistic patterns:

| Avoid | Replace with |
|-------|-------------|
| "John Doe" | "Sarah Chen", "Marcus Rivera" |
| "$5.00" | "$0.0425/kg", "$2,847", "$12.50/mo" |
| "#1234" | "ENG-2703", "FIN-0042" |
| "3 days ago" | "12 minutes ago", "2 hours ago" |
| "Lorem ipsum" | Real copy from the domain |
| "5 stars" | Specific: "4.9/5 (2,847 reviews)" |
| Generic avatars | Diverse, realistic photos |
| "99% uptime" | "99.999%", "three 9s", "five 9s" |
| "10x faster" | "3.2x faster", "47ms median response" |
| "Trusted by many" | Named logos, specific count |

Rule: precision signals authenticity. "$2,847" is more credible than "$3000". "99.999%" is more credible than "100%". Real decimal values beat round numbers.

#### Step 7: Section sequencing checklist

Order sections by answering: what does the reader need to know next?

- [ ] Each section either advances the narrative or provides essential evidence
- [ ] No two adjacent sections have the same tonal register
- [ ] No two adjacent sections use the same layout pattern
- [ ] The first scroll creates desire to continue (open loop, visual hook, or unanswered question)
- [ ] The CTA appears when the reader has enough information to decide
- [ ] Critical information is at L0-L1, not buried at L3
- [ ] Data display format matches information type (see grammar table)
- [ ] All placeholder content replaced with credible, specific data
- [ ] Density mode is intentional per section, not uniform
- [ ] Section separators are proportional to the tonal shift between sections

## Anti-patterns I avoid

- Generic section order (hero → features → testimonials → CTA) without narrative logic
- Equal visual weight for every section — rhythm requires variation
- Every section in a card — whitespace and similarity group better than borders
- Round numbers and generic data — precision builds trust, roundness signals fabrication
- All sections at the same density — compact/standard/comfortable create visual variety
- Burying the value proposition at L3 — if the reader needs to scroll 5 times to understand what you do, they won't
- Open loops without closure — tease in L1 must resolve by L2
- Social proof before the reader understands what the product is — proof without context is meaningless
